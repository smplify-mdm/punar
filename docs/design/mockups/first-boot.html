Sect I · The fork register

The fork is unmanaged-first as law: personal is the pre-selected default, and the organization is a card, not a gate.

01Default card

Personal arrives selected, carrying the only DEFAULT tag in the flow. Its copy is the whole promise in nine words: your device, your rules, nothing leaves this machine. spec §65 · §3.6

02Org card copy

The organization card states exactly what changes — a baseline and visibility — and adds the standing rule that everything the organization can see is always shown to the user too. spec §24.2

03Enroll later

The card's own footer says enrollment can happen any time and never applies retroactively — so choosing personal today costs nothing tomorrow. spec §49 · design language §8

04Additive chrome

After the org path completes, the only visual change is the masthead gaining a line and a compliance pill. Enrollment annotates the surface; it never restructures it — the same demonstration the AI panel's mode toggle makes. design language §8

Sect II · Telemetry honesty register

The privacy stage states facts; it does not stage a negotiation.

01The sentence

Community edition has no telemetry, so the stage renders that as a fact block — THERE IS NOTHING TO OPT OUT OF — instead of drawing a toggle for data that is never collected. spec §54

02Relay is a choice

Private relay is the one real decision on the stage: off until chosen, one line of consequence, and a dashed SIMULATED · M12 tag because the relay path is not yet a production claim. spec §33 · §1.22

03No opt-out theater

Nothing on this stage is pre-checked consent, dark-pattern copy, or a "share diagnostics" plea. A screen with no status to report contains no color — and no bargaining. design language §2

Sect III · Enrollment chain register

The organization path is the §49 chain drawn as a progress register — six steps, every claim marked.

01Chain order

Discovery, authentication, registration, attestation, desired state, provision — the spec's sequence verbatim, each step a register row with a status dot that fills ok-green only when that step has actually completed. spec §49

02Attestation honesty

Attestation carries a dashed SIMULATED · VM tag: in MVP builds there is no real TPM measurement, and the drawing refuses to pretend otherwise. spec §1.22 · §44.1

03Mocked control plane

The whole path talks to a mocked Smplify control plane until Milestone 5 — so the plate names the fixtures (alice@acme.com · dev_123 · eng-baseline-v12 · eng-ai-v3) rather than inventing a live service. spec §49 · §76 M5

04Visibility line

The chain ends with the employee-facing promise, not a corporate one: enrolled means you see everything they see. It is the §24.2 rule stated at the moment it starts to matter.

Sect IV · Keyboard register

First boot is completable start to finish without a pointer — and without a terminal.

01No shell

No stage shows, requires, or suggests a shell command. The spec's first-boot rule is absolute, and the demo honors it down to the footer. spec §65

02Arrow grammar

← → move between stages along whichever branch the fork selected; ↵ acts on the current stage; single letters (P · O · R) make the fork and relay decisions. Bindings are printed in the frame footer, not hidden. spec §12

03Underline inputs

Name, passphrase, and Wi-Fi credential fields reuse the greeter's underline-input grammar — the same hairline, the same focus ring, learned once at first boot and kept forever.

Sect V · Implementation notes

Design mockup — the personal path ships with Milestone 1; the organization branch goes live with the mocked control plane in Milestone 5.

01Personal path

Stages 01–05 and 07 are a Quickshell OOBE surface consuming shell/theme/punar-tokens.json, shipped on the M1 ISO/VM image. No custom installer beyond this flow before the core OS works. spec §66 · §76 M1

02Org branch

Stage 06 calls the enrollment chain against mocked Smplify (M5); attestation stays dashed until real Secure Boot/TPM measurement exists. The relay toggle wires to the network privacy prototype in M12 and stays labeled simulated until then. spec §76 M5 · M12

03Handoff

ENTER DESKTOP performs the same 450ms first-light handoff the greeter uses — one spatial transition, once, into Punar Shell with terminal, browser, and workspace creation one keystroke away. spec §65 steps 7–11
