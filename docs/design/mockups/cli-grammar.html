Terminal output is designed, not dumped.

The shell is keyboard-first, but the terminal remains exceptional — so the CLI is part of the design language, not an escape from it. Every punarctl verb calls the same typed capability the graphical shell calls, and its output arrives in the same grammar: tracked mastheads, middle-dot separators, tabular columns, and color only where there is status.

Sect I · One-layer register

punarctl is not a wrapper around shell scripts — it is the same typed capability call the shell makes, printed in the house grammar.

01Capability parity

Every verb resolves to a typed capability — SetFirewall(enabled), InstallApplication(package) — through the same policy layer as the GUI. RunRootShell(command) is prohibited by architecture, not by convention. spec §10

02Verb set

The five outputs drawn here cover the §11.2 surface: status, policy explain, agents inspect, plus punar-env up (§17) and the in-terminal approval prompt (§28). The remaining verbs reuse the same four grammar rules — nothing needs a new idiom.

03Same data, same order

policy explain prints the exact anatomy of System Control's explain card (Plate D-004); agents inspect prints the AI panel's authority-then-ledger stack (Plate D-005), MAY and DID kept structurally apart. One dataset, two typefaces. spec §40 · §21 · §25

04Exceptional terminal

"The graphical shell is keyboard-first, but the terminal remains exceptional" — a rule this plate takes literally: the CLI gets designed output because for many users it is the primary surface, not the fallback. spec §82 · §3.2

Sect II · Grammar register

Four rules make a screen of text read as Punar: tracked mastheads, middle dots, tabular columns, and color spent only on status words.

01Masthead + rule

Output opens the way every surface opens: PUNAR · STATUS left, context right, closed by a heavy rule. In a real terminal the rule is a run of box-drawing U+2500; this mockup draws it as a border for crispness.

02Middle dots

Fields join with ·, never pipes or slashes — AGT_123 · ALICE@ACME.COM · ATLAS-DEV-42 is the same attribution line the approval overlay prints. One separator everywhere means output is scannable before it is read.

03Columns

Labels are tracked uppercase in bright-black; values sit in aligned tabular-nums columns; decisions hold the right edge so reading straight down tells the whole story — the D-005 rule, kept in monospace.

04Status color

The ANSI slots map 1:1 to decisions and states (§52): lime for allowed/compliant/ready, peach for approval-pending, red for denied/unknown. DEVICE · PERSONAL stays uncolored — the absence of an organization is calm, never a warning. design language §8

Sect III · Scriptability register

The pretty output is for humans. Every command keeps a machine spelling, and the two never disagree.

01--json flag  Planned · M3

Every verb takes --json and emits the capability-registry field names verbatim (current_state, managed_by, verification) — the human table and the JSON are two renderers over one struct. Dashed until punarctl ships. spec §41 · §11.2

02Pipes strip color

When stdout is not a TTY, or NO_COLOR is set, ANSI codes drop and columns stay — grep and awk see clean fields, and no script ever parses an escape sequence.

03Exit codes  Planned · M3

0 for success, distinct nonzero codes for deny, approval_required, and drift — so the policy decision values (§20) are testable from a shell script without reading prose.

Sect IV · Implementation notes

Design mockup — the CLI lands with punarctl in Milestone 3 and grows verbs as its services ship; this page is the output acceptance reference.

01Milestone map

status and policy explain ship with punard + punarctl (M3–M4); punar-env up with the environment manager (M6); agents inspect with registry and ledger (M7–M8); the in-terminal approval prompt with approval gates (M9).

02One formatter

A single output library in punarctl renders masthead, rule, row, and decision — no command formats itself. The terminal palette is design-language §6 v0 (#08090A / #F2F3F5, lime cursor); tuning the blue/magenta/cyan slots is an M1 task.

03Approval TUI

The 05 prompt is the agent gateway (§26) speaking through the terminal: the same apr_123 contract block as Plate D-003, same expiry, same audit line either way. Approve is the surface's one filled control — inverse-video lime; deny stays a red ghost. spec §28
