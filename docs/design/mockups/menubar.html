Nothing appears in the bar that you cannot open.

Today's bar names a workspace and tells the time. Underneath it, punard, punar-agentd and Hyprland already know which agents are running, which approval is counting down, and whether something unrecognised started talking to a model. The bar carries exactly that much — a fixed row of slots, each one a doorway to the surface that owns it, reachable in one chord. On a personal, idle machine it says two things and looks finished.

Sect I · Zone register

Three zones, one of them deliberately empty — and a slot is earned, never granted.

01Left · identity

PUNAR · <workspace> — brand in ink, context in ink-3, the masthead grammar the shipped bar already uses. It answers where am I, never what is wrong. A named project workspace prints its name; an unnamed one prints its number. Nothing else ever lands here — not the org, not the app, not a launcher. design language §5 · spec §14.1

02Centre · reserved

Empty, and reserved for exactly one class of thing: modality. When a submap is active the centre prints the instrument chip already specified in D-007 — RESIZE · HJKL · ESC — state, verbs, exit. Modes are transient and self-cancelling, so the centre is empty almost always; status is persistent, so it may never move in here. Giving status the centre would put the loudest thing in the calmest place and leave the bar with nowhere to announce a mode. spec §12.3

03Right · the cluster

Fixed order, left to right: AI · ENV · CRED · APPROVAL · ORG · CLOCK — by lifecycle (what you started, what you hold, what waits on you, what watches you, then time). Severity never reorders anything: position is stable so muscle memory holds, and urgency is carried by colour, word and focus-landing instead. 8px middle-dot gutters between slots, 12px bar margin, 30px bar height, clock always last and always tabular so its width never jitters. The cluster is right-anchored and grows leftward into empty space, so the clock and the org annotation never jump under the pointer. design language §1 · §5

04What earns a slot

All four must hold. Observable — the fact arrives on a file or IPC event the shell already receives, with no poll and no inference. Live — it is running, pending or expiring right now; configuration belongs in System Control. Owned — some surface owns it, so activating the slot is a doorway and not a dead end. Absent when over — the slot disappears when the thing stops, so its presence is information. Battery, Wi-Fi and volume fail live at rest: they earn a slot only when they have something to say. spec §1.22 · §6.3 · §63

05Overflow · 1366 × 768

Slots shed detail, never presence — there is no overflow menu, because a hidden alarm is a missable alarm. Ladder, first to give up: workspace subtitle → environment name → credential name → agent name → org name truncated at 12ch → compliance word (the dot keeps the colour). Never collapsed at any width: the words UNKNOWN AI, the approval countdown, and the clock. If the row still overflows after that, the identity zone truncates before any of those three. spec §5.1 · §11.8

Sect II · The calm register

The default bar is two facts wide, and it is the finished design — every other state is a temporary annotation on it.

01The calm rule

Personal, idle, nothing running: PUNAR · 1 at the left, empty centre, 08:26 at the right. No cluster, no separator, no colour, no icons, no placeholder greyed-out widgets waiting to light up. A masthead with nothing to report is complete, not empty — the hairline rule closing the bar is what makes it read as finished. This is state 01 in the frame, and it is what the shipped bar already renders today. design language §2 · §8

02How it grows

Slots arrive one at a time from the right cluster, each on a single 300ms fade-and-4px-slide on the standard curve, and leave on a 150ms fade followed by a 300ms width collapse. The bar's height, background, rule and type never change — growth is horizontal and additive only. It never becomes two rows, never changes colour as a whole, never reflows the left zone. spec §13.4

03Colour discipline

The bar spends no colour on things that are merely true. A running agent, a live environment, a valid credential are facts and render in ink. Colour appears only for a decision or a deviation: warn for pending and expiring (an approval, a credential under five minutes, a remediating device), bad for an unrecognised AI process or a non-compliant device. Consequence: the calm bar and the working bar are both monochrome, and the first colour a user ever sees in the bar means something. design language §2 · spec §52

04The unmissable one

An unknown AI detection is the only slot allowed four reinforcements at once: a word and not a glyph (UNKNOWN AI 1 — an icon can be ignored, a sentence cannot), the bad colour on word and dot, one arrival animation, and immunity from every collapse rule. It is deliberately phrased as an observation, never a guarantee — the bar counts what was detected and never claims the absence of what was not. The out-of-band alert belongs to the notification plate; the bar is the residue that stays until it is dealt with. spec §23 · §1.22

05What may never animate

Anything at rest. No pulsing dot, no blinking, no spinner, no marquee, no progress sweep, no second hand. A changing count cross-fades its numeral over 150ms and does not count up. A countdown is a text substitution, not an animation. Reduced-motion collapses all of it to instant opacity. spec §13.4

Sect III · Doorway register

The keyboard is the primary path into the bar, because the bar's most urgent item must not also be its most expensive to reach.

01The chord

SUPER + B focuses the status cluster. Focus lands on the leftmost slot — unless something is warn or bad, in which case it lands on the highest-severity slot, because if the bar is shouting you almost certainly pressed the key because of it. ← → (and H L) walk the visible slots without wrapping, so the ends are felt. ↵ opens the owning surface. ESC releases focus back to the window that had it. spec §12.1 · §13.3

02Why not a tray

On a full-screen tiling desktop a mouse-only tray costs a pointer trip of the entire display height into a 30px target, and it prices information by how alarming it is — exactly backwards. The chord costs the same two keystrokes whatever the bar is showing, composes with the rest of the SUPER family, and satisfies the requirement that every first-party workflow be keyboard-operable. The mouse still works: click focuses a slot and opens its popover, a second click or ↵ opens the surface. spec §3.3 · §12.1 · §12.3

03Every slot is a door

Agents → AI panel (SUPER+A). Approvals → the approval overlay. Credentials → the AI panel's authority view. Environments → the project workspace detail. Org and compliance → System Control. Workspace → the overview (SUPER+TAB). The destinations already own their own chords; the bar's model is the discovery path, not the only one. A slot with no destination is a slot that should not exist — which is the scope of the claim above the fold: it binds the cluster. Identity and the clock are not slots and open nothing, and that is why neither of them is ever allowed to carry status. spec §12.2 · §63 · §14.2

04Popover anatomy

Focus and hover both open it; it is 268px wide, anchored to the slot's right edge, clamped inside the display, and never covers the clock. Five parts, in order: a tracked mono title with the count; a hairline; at most three rows of detail in registry vocabulary, with "and N more" beyond that — it never scrolls, because the bar summarises and the owning surface details; a source line naming the file and its freshness (/run/punar/agents.json · scanned 10:00:02) so the OS shows its evidence; and one action line — ↵ Open AI panel · Super + A. No other buttons. Nothing in a popover is destructive, and nothing in a popover is the only way to reach something. spec §40 · §73

05Focus is not theft

The bar takes keyboard focus only while the cluster is focused, and gives it back on ESC or on any click outside. At rest the layer surface requests no keyboard focus at all, so typing into an editor can never fall into the bar. The focus ring is a 2px ink ring drawn inset — a 30px bar has no room for a 2px offset — and carries no colour dependence. design language §9.4 · spec §12

Sect IV · Data-source register

Every slot names the event that produces it; the two that have no event yet are drawn dashed and do not render on a real machine.

01Workspace · M2 · shipped

Hyprland socket2 events through Quickshell.Hyprland (focusedWorkspace), with persisted names from ~/.local/state/punar/workspaces.json. Event-driven; a rename lands the moment renameworkspace fires. Already live in Bar.qml. spec §14.1

02AI sessions · M7 · shipped

/run/punar/agents.json → counts.managed + counts.observed, followed by the existing Agents singleton's FileView inotify watch. No new plumbing: the cluster binds to properties that already exist. Solid stroke. ipc.md §11 · spec §19

03Unknown AI · M7 file / M10 quality

Same file, counts.unknown and detections[] (classification, suspected, observed_at). The file contract ships; detection quality is Milestone 10, and the honest reading of spec §23 is that this slot reports what was detected and never implies completeness. Freshness comes from a one-shot punarctl agents list --json on user action — never a loop. spec §23 · §6.3

04Approvals · M9 · in flight

/run/punar/approvals.json — pending summaries with expires_at, written atomically by punard on every queue change, watched with the same FileView pattern. Milestone 9 is being built right now, so the slot is drawn dashed here and must not render until the file exists. The countdown is computed locally from expires_at; the file is not re-read to tick. spec §28 · design language §7

05Credentials · M9 · in flight

Short-lived grants with TTL, same milestone, same side-contract shape — a grants[] array alongside the approvals, carrying credential name, project and expires_at only. Never the token, never a fingerprint of it. Dashed until M9 lands. spec §29

06Environments · the gap

No data source today. punar-env containers are reachable only by running podman, and running podman on a timer to fill a bar slot is exactly the polling loop §6.3 prohibits. The fix, and the only acceptable one: punar-env writes /run/punar/envs.json — {v, envs:[{project, name, state, started_at}], ts} — atomically (tmp+rename in /run/punar, 0644) on up, down and destroy, exactly as punard does for status.json and agentd for agents.json. Until that file exists the slot does not render at all. Marked M10+, dashed in the frame. spec §17 · §11.6 · ipc.md §9 · §11

07Org · compliance · M5 · shipped

/run/punar/status.json → enrolled, org_name, compliance_overall, through the existing Status singleton. Fails closed to personal on a missing or unparsable file — an unenrolled machine renders no org chrome and no "unenrolled" warning. Already live in Bar.qml. spec §52 · §49 · design language §8

08Clock · M1 · shipped

Quickshell SystemClock at Minutes precision — one wake per minute, the only unconditional timer the bar owns. Geist Mono is inherently tabular, so the width is stable across every minute. spec §6.3

09Battery · net · audio

Quickshell services exist; nothing is wired. Design-ready, implementation Milestone 11. When wired they follow the §04 slot rule rather than the tray habit: battery appears at ≤20% or on a critical discharge event, network appears when down or when the relay is off, audio appears only while muted with an active stream. A charged laptop on Wi-Fi shows nothing, which is the point. spec §12.1 · §33

10Countdown ticks

The bar owns no timer at rest. A tick timer exists only while a countdown slot exists: 60s interval while more than a minute remains (whole minutes rendered), 1s interval under a minute, stopped and destroyed when the last countdown slot disappears. It performs no I/O — it re-renders a local subtraction against a timestamp already in memory. That is the whole of the concession to §6.3, and it is bounded by how long an approval can be pending. spec §6.3 · §28

Sect V · Implementation notes

Design mockup — the calm bar ships today; the cluster is one new component and two new singletons on top of it.

01Bar.qml

Unchanged in structure. The right-hand Row gains exactly one child before the org labels: StatusCluster { }. The existing visible: gating on the org chrome stays as the template — Row positioners already skip invisible items, which is precisely the "grows leftward, clock never moves" behaviour the zone register asks for. shell/punar-shell/Bar/Bar.qml

02StatusCluster.qml

New Bar/StatusCluster.qml: a FocusScope wrapping a Row of fixed-order StatusSlot children, each bound to a Services singleton and each with its own visible: expression. Keys.onLeftPressed/onRightPressed walk the visible children, Keys.onReturnPressed emits activated(slot), Keys.onEscapePressed drops focus. Order is child order in the file — there is no sort function to get wrong. spec §11.8

03StatusSlot.qml

New Bar/StatusSlot.qml: label, value, severity ("none"|"warn"|"bad"), operating (false draws the dashed underbar, the §7 production-claim rule applied to our own chrome), detailLevel (3→0, driven by the cluster measuring implicitWidth against available width — pure layout, no data change), and an activated() signal. Reuses Bar.qml's MetaLabel grammar verbatim. design language §7 · §1

04New singletons

Services/Approvals.qml and Services/Envs.qml, both copies of the Status.qml shape: a FileView with watchChanges: true, onFileChanged: reload(), a defensive JSON.parse in a try, and a resetEmpty() fail-closed path so a missing file renders no slot rather than an error. Registered in Services/qmldir. Agents and Status need no changes at all. ipc.md §9 · §11

05Focus and popover

A Hyprland global bind SUPER, B dispatches to the shell, which calls cluster.forceActiveFocus() and raises WlrLayershell.keyboardFocus from none to exclusive for the duration — the bar must never hold keyboard focus at rest. The popover is a separate PopupWindow on the overlay layer, visible: cluster.focusedSlot !== null, positioned from the slot's mapped x. spec §12.1

06States not drawn

The modality chip in the centre zone is specified here and drawn in D-007, not repeated. Battery, network and audio slots are specified in words (Sect IV·09) and will be drawn when M11 wires them. Multi-monitor bar duplication and per-monitor workspace labels follow spec §15 and are not claimed by this plate. All dashed, none solid.
