Sect I · Workspace register

Project context is a native operating-system concept — this surface is where that sentence becomes furniture.

01Masthead

ATLAS · WORKSPACE 1 — the project is named before anything else is shown, the same identity-first masthead as every plate. The number is an address; the name is the concept. spec §14 · §82

02State list

The five sections are §14.1 verbatim: windows, environment, AI sessions, network policy, temporary credentials. A workspace is the sum of these — the panel proves the claim by listing nothing else. spec §14.1

03Switcher

SUPER+1–9 chips carry project names, not just digits; empty slots stay dashed until a project claims them. The graphical overview is SUPER+TAB with arrows, Enter, and type-to-search. spec §14.2

04Personal default

The demo opens unmanaged: the same Atlas, the same boundaries, sourced from YOUR RULES. Enrolling adds the MANAGED pill, the org line, and a policy citation — annotation, never restructure. spec §3.2 · design language §8

Sect II · Environment register

The dev environment is a security boundary that happens to be convenient.

01Manifest

The rows render the §17 Atlas fixture exactly: devcontainer, node 24, rust stable, postgres — plus the permissions block that becomes the Network and Credentials sections below it. One file declares the whole workspace. spec §17

02Lifecycle

The statebar buttons are the actual commands — punar-env init / up / shell — and the env chip states the claim: declared, running, attached. The chip never says more than punar-env status would print. spec §11.6

03Agent launch

punar-env agent claude starts Claude Code inside the boundary as agt_123 — registered, attributed, and subject to the same network table as everything else in the workspace. Inspection is one keystroke away in the AI panel. spec §17 · §27

Sect III · Network register

Three rows tell the whole story, and the colors are the policy decisions themselves.

01Atlas table

The §36 example verbatim: Internet ALLOW green, Acme Dev ALLOW green, Production DENY red. Green and red are the §20 decision words wearing their one meaning — no decoration anywhere else on the surface. spec §36 · §52

02Named source

Personal mode cites YOUR RULES · PROJECT MANIFEST; managed mode cites ENG-BASELINE-V12 + PROJECT MANIFEST. Authority always has a named source, whoever set it — the table itself never changes shape. spec §39 · §40

03Enforcement depth

The note under the table states where the boundary lives: below the agent, applied to every process in the workspace. An AI session cannot route around a rule its shell is inside of. spec §36 · §45

04Short-lived keys

AWS DEV shows a live countdown, amber in its final five minutes — credentials are brokered, scoped to the workspace, and expire by design. Production credentials render red and stay red. spec §29

Sect IV · Restoration register

Punar remembers the layout today; the rest of the promise is drawn dashed until it operates.

01Layout memory

Window positions and workspace assignment are remembered and restored — a solid-stroke claim, shipped with native multitasking. spec §14.3 · M2

02Future restoration

Application reopening, terminal state, browser context, container reconnection, and AI session state where safe are §14.3's future goals — described here in words, dashed in drawings, never rendered as if they worked. spec §14.3

03Activity model

The dashed card in the frame is §14.4 honestly held: a temporary activity like INVESTIGATE PRODUCTION INCIDENT bundles windows, credentials, and network access, and ending it revokes the temporary authority. Not yet drawn, so it says so. spec §14.4 · §36

Sect V · Implementation notes

Design mockup — the workspace surface assembles across Milestones 2–12; this page is the acceptance reference.

01Workspaces

punar-workspace (§11.5) owns named contexts and layout memory; M2 delivers tiling, overview, and named project workspaces. The switcher strip is shell chrome over the same service.

02Environment

punar-env (§11.6) with Podman/devcontainer lands in M6, Atlas fixture included — the Environment section reads its status call directly. Agent launch wires to the registry in M7.

03Network + keys

Project-route policy and observability come with punar-netd in M12; the credential rows read the M9 secret broker. Until those land, this panel renders fixtures — and would carry SIMULATED tags if shipped early.
