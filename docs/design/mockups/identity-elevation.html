Sect I · Privilege register

There is no permanent root — there is a reason, a grant, and a clock.

01The dialog

The sibling of the D-003 approval card, with one inversion: the requester is you. Same contract grammar — who, what, how long, under which policy — because a human asking for privilege deserves the same clarity an agent gets. CLI parity is literal: punarctl privilege request --capability system.install-package --reason "…". spec §48

02Reason field

The underline input from the greeter's grammar, and it is required — Authorize stays unfilled until a reason exists, because the reason travels verbatim into the audit event. spec §53

03Countdown chip

ELEVATED · 14:32 REMAINING lives in the shell bar for the life of the grant — green while active, amber in the final minute, gone when it expires. Privilege is never invisible, and revoke is one keystroke. There is no generic unrestricted root-shell API to fall back to. spec §48

04Auto-expiry

At 00:00 the grant drops itself and the dialog returns to its unprivileged state. Extending means asking again, with a reason, again. Fifteen minutes is a policy value, not a constant.

Sect II · Broker register

A credential is an event with an expiry, not a file with a location.

01Issuance card

The §29 request rendered as a card: user, agent, project, credential, TTL — alice@acme.com · claude-code · atlas · aws-dev · 3600. The broker evaluated device, compliance, and policy before this card existed; the card is the receipt.

02Privacy line

NEVER WRITTEN TO DISK · NEVER LOGGED — the §53 redaction rule stated on the surface, and enforced on the surface too: the UI has no affordance that could show the value. Expiry is the only property worth drawing. spec §29 · §53

03Deny voice

The aws_prod card is §73 verbatim: what happened, why, which policy, and the next step — an amber approval path when managed, a System Control pointer when personal. The agent received the same sentence. spec §73 · evt_502

04Mock honesty

The dashed SIMULATED · MOCK PROVIDER tag stays on the card until a real provider ships — §29's MVP is a mock with expiration, deny path, and redaction tests, and the drawing claims exactly that much.

Sect III · Identity register

Seven nouns, one chain — every surface on this plate prints the same graph.

01The graph

Organization → Device → User → Project → Application → AI Agent → Service. Every privileged event on this plate is attributable through it: the elevation grant, the issued credential, the denial. spec §47

02One grammar

The attribution line — ALICE · DEV_123 · ATLAS — is the same tracked-mono row as the approval overlay's identity chain and the AI panel's session line. Learn it once; it never changes shape.

03Personal chain

An unmanaged device keeps the whole chain minus the organization. Attribution is a user benefit first: your own audit trail of what held privilege, when, and why — with no one to report it to.

Sect IV · Lock register

Leaving the machine is the same surface as arriving at it.

01Greeter sibling

Same masthead, same tabular clock, same underline passphrase field as Plate D-002 — the only difference is what is behind it: a running session instead of a fresh one, and the footer says so.

02Unlock button

Unlock is a named consequential affirmative in the action-color rule, so it carries the ok-green fill — the one colored button on the surface, exactly as Sign in does on the greeter.

03Managed chrome

Enrollment adds the org line and the compliance pill to the masthead — and nothing else. The personal lock is calm paper with no absence to apologize for. design language §8

Sect V · Implementation notes

Design mockup — privilege and the broker land with punard; the lock ships with the greeter.

01Privilege

A typed capability in punard backed by polkit and transient group membership — Milestones 3–4. The bar chip is punar-shell; the dialog and punarctl privilege request call the identical capability. spec §10 · §48

02Broker

punar-secrets (§11.4) with the §29 mock provider; issuance surfaces arrive with the agent milestones (M7–M8). Redaction tests are the acceptance gate — this card may never be able to render a secret value.

03Lock

A Quickshell lock module sharing the greeter's QML components and shell/theme/punar-tokens.json — Milestone 1. Failed-attempt states (shake, TRY AGAIN, bad-red on third failure) are specified in D-002's words and stay dashed until drawn.
