Sect I · Channel register

A version is a date you can point to — a vendor-pinned snapshot, promoted per channel, never a moving target.

01Snapshot pin

The masthead pill reads CHANNEL · STABLE · SNAPSHOT 2026/08/20 — the whole package set is one pinned date on the vendor mirror. Reproducible by construction, citable in an audit. spec §8.1 · ADR-001

02Endpoint fields

The key–value block is the §57 endpoint verbatim: current version, desired version, channel, health, rollback state. The panel renders what punarctl update status prints — same data, same order. spec §57 · §10

03Ring meter

Managed mode draws the staged rollout as a segmented tick meter — CANARY / 10 / 50 / 100 with the health gate named between stages and the device's own ring marked YOU in a dashed segment (not reached yet: not a claim). spec §57

04Personal promise

Unenrolled, the meter does not exist — the card says updates arrive when stable and offers the one colored button: Apply, ok-green, the commit action. No rings is not a downgrade; it is the default state. design language §8

Sect II · Browser split register

Browser security updates ride a faster channel — the row says so, with its own date.

01Own row, own date

Chromium's last-updated date (2026/08/23) sits beside the OS snapshot date (2026/08/20) — visibly newer, because emergency browser patches never wait for an OS release. spec §58 · §30.2

02Org staging

Managed mode prefixes the row with ORG-STAGED — staged enterprise browser rollout is an annotation on the same row, not a second screen. spec §58

03History parity

Browser updates land in the same local history with the same evt_ ids as OS updates — one audited timeline, two cadences. spec §53

Sect III · Rollback honesty register

Solid strokes for the rollback that ships; a dashed tag for the one that is a trajectory.

01Ghost action

Roll back is an ink ghost button naming its target snapshot (2026/08/13) — consequential but not destructive, so it takes no color. Bootable-snapshot restore is the shipped MVP mechanism. ADR-001 · spec §57

02A/B tag

The A/B IMAGE SLOTS · SIMULATED · TRAJECTORY tag is dashed because A/B updates are the declared production path, not an operating one — implementation alone would not earn a solid line, and a plan certainly does not. design language §7 · spec §1.22

03History tells rollbacks

evt_501 records a real rollback in the visible history — the surface does not pretend updates never fail; it shows that failing was recoverable. spec §42 · §43

Sect IV · Application policy register

Required, denied, and yours — three words, and every denial explains itself in sentences.

01Personal list

Unenrolled, the applications view is a plain list. allowUserInstall is the user's own default; there is no empty "policy" chrome waiting to be filled. spec §46 · §20

02Required pins

Managed mode pins git and podman with a MANAGED · REQUIRED pill citing eng-baseline-v12 — annotation on the existing rows, never a reordering of the list. spec §46 · §49

03Denial voice

The denied card answers the §73 questions in order: what happened, why, which policy, whether an exception is possible, and the next step — with the amber approval tag, never a bare EPERM. spec §73 · §46 · §28

04Stable semantics

Required / denied / allowUserInstall are the surface's whole vocabulary — they must survive any change to the underlying package system, so the panel never names one. spec §46

Sect V · Implementation notes

Design mockup — the channel exists from Milestone 0; this page is the acceptance reference for the surface that reports it.

01Substrate

Vendor-pinned snapshot channels and mkosi-signed images land with the substrate (M0–M1, per ADR-001); snapper bootable-snapshot rollback is the M1 mechanism the Roll back button calls. A/B slots stay dashed until the production update path operates.

02Control plane

The §57 endpoint fields are served by punard (M3–M4); ring assignment and the rollout meter go live with mock Smplify enrollment (M5). Until then the managed state on this page runs on fixture data — which is why the whole demo is a mockup, labeled as one.

03Applications

The applications view reads the §46 policy document through the capability registry (§41); required-app reconciliation and the denial explain reuse the §40/§73 machinery already drawn in Plate D-004. Browser channel wiring is the §58 pipeline, staged per §30.2 cadence.
