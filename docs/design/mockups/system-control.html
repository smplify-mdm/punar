Sect I · Structure register

Six sections, one rail, one grammar — and the CLI sees exactly the same capabilities.

01Masthead

Device identity and org left, compliance and date right — the same masthead as the greeter and command center. Every first-party surface says where you are. spec §63

02Rail

The §63 taxonomy verbatim: System, Security, AI, Developer, Privacy, Organization. Items are sans; section heads are tracked mono. Selection is the raise-fill + 2px ink rule, same as everywhere. Status dots appear only where there is status.

03Search

/ filters the rail live — reach any setting in two keystrokes. The underline input is the greeter's passphrase field grammar reused.

04Parity line

The footer states the architecture: this panel and punarctl call the same typed capability layer. Nothing here is a special path. spec §10

Sect II · Managed-control register

The firewall view is the §73 anatomy: what, why, who, which policy, can you change it, what next.

01Locked toggle

The switch renders on and live — with a MANAGED pill beside it, never disabled-gray. State stays legible; ownership is explicit.

02Explain block

The punarctl policy explain output rendered as a card: effective value, source policy, override permission, compliance. Same data, same order, both surfaces. spec §40

03Drift promise

The view states what happens if the setting is changed outside Punar: detection, remediation, audit. No surprises later. spec §43

04Exception path

The amber REQUEST EXCEPTION tag is the approval_required decision wearing its color — it opens the approval flow from Plate D-003, not a settings hack.

Sect III · Honesty register

Simulated is labeled. Undrawn is dashed. The panel cannot overclaim.

01Simulated tag

Boot Integrity in the compliance view carries a dashed SIMULATED tag in VM builds — the §1.22 rule enforced at the pixel level, matching the plate stroke semantics.

02Undrawn state

Items without a finished design open a dashed placeholder naming itself undrawn — the design system applies its own production-claim rule to itself.

03Unknown AI row

The Agents view shows the shadow-AI fixture as a bad-red row with INSPECT — visibility before enforcement, matching the §25 panel it links to.

Sect IV · Implementation notes

Design mockup — System Control ships across Milestones 1–5; this page is the acceptance reference.

01Shell

Quickshell full-surface window (not an overlay card), tokens from shell/theme/punar-tokens.json. M1 ships the frame + System section stubs; Security/Organization views go live with punard (M3–M5).

02Data

Every view reads the capability registry (§41) and policy engine (§40); the compliance table is the §52 states verbatim. Wi-Fi connect calls ConnectWifi(network) — the row prints it.
