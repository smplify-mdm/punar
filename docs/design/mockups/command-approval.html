The command center never generates a shell string — every row is a capability-registry entry, and the row says so.

01Context head

Active project and compliance state ride along in the masthead — the overlay always says where you are and whether the device is in good standing. spec §52 · §63

02Result rows

Glyph tags instead of app icons: two-letter mono codes in bordered squares keep the surface monochrome and instantly legible. Selection is a raise fill plus a 2px ink rule — no color spent.

03Intent resolution

"Connect my headphones" resolves to ConnectBluetooth(…) and the row prints the typed capability it will call. The contract is visible before Enter. spec §10 · §12.2

04Questions

"Why can't Claude access production?" answers inline with the effective policy, its source, and the next step — the §40 explain surface, reached from the same input as app launch. The exception path is an amber tag because it is an approval_required decision.

An approval is a contract card: who is asking, for what, under which policy, for how long, and what exactly happens on yes.

01Identity chain

The full attribution graph on one mono line — principal kind, agent, project, session, human. Every privileged event stays attributable. spec §22 · §47

02Countdown

Live tabular-nums expiry in the masthead; it turns warn-amber under a minute and the request auto-denies at zero — expiration is a first-class outcome, audited like any decision. spec §28

03Contract block

Between hairlines: the exact typed capability that will run, the policy that gates it, and the audit promise. Approving executes InstallPackage(libvirt) once — never a root shell. spec §10 · §60

04Actions

The action-color pair: green filled Approve, red ghost Deny, keyboard-first with visible bindings. Esc defers without deciding — dismissal is not denial.

Sect III · Implementation notes

Design mockups — Milestone 1–3 build these; the registers above are the acceptance reference.

01Shell layer

Both are Quickshell layer-shell overlays over the compositor, consuming shell/theme/punar-tokens.json. The scrim is the warm ink wash at 22%, never a blur-only dim.

02Data path

Command rows come from the capability registry (§41) and application index; explain answers from the policy engine (§40); approval cards from punar-agentd's typed approval API (§28) with expires_at driving the countdown.

03States not drawn

Multi-approval queue (badge in the masthead), unmanaged-agent warning variant, offline behavior, and the scratchpad/AI panel siblings. Dashed until drawn.
