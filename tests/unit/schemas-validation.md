# Schema validation harness

The contract layer is exercised by `tools/validate_schemas.py`, run in Docker via `tools/validate-schemas.sh` (`python:3.12-slim` + `jsonschema`/`pyyaml`/`referencing`; the host needs no local Python packages). The harness metaschema-checks every schema under `schemas/**/` against JSON Schema draft 2020-12, resolves all `$ref`s (including `schemas/common/defs.json`) from the local tree by `$id` via a preloaded registry — never over the network — and then validates every example under `schemas/**/examples/` and every fixture under `fixtures/**/` (JSON and YAML) against the schema named by the explicit `MANIFEST` at the top of the script (mapping rules mirror `fixtures/README.md`; files in an `invalid/` directory must fail validation, `fixtures/organizations/acme/org.json` is deliberately skipped as it has no schema yet, and any unmapped document is an error). Output is per-file pass/fail and the exit code is nonzero on any failure, so CI can simply run `tools/validate-schemas.sh` as a job step once `.github/workflows/ci.yml` (owned by the concurrent OS/build workflow) wires it in. Status as of 2026-08-24: green — 14 schemas metaschema-checked, 111 documents validated, all pass (the fail path was also verified to exit 1 against a deliberately broken fixture). Reconciling `crates/punar-common` Rust types with these schemas is deferred Milestone 3 work and is not covered by this harness.
