Sect I · Window-grammar register

Four window modes, one chord family — the grammar is the interface, not the chrome.

01The table

The §13.3 table verbatim: SUPER+H/J/K/L focus, +SHIFT moves, R resize, F fullscreen, TAB overview, 1..9 workspaces, SPACE command center. Bindings may evolve; the family does not. spec §13.3

02Modes

Tile, stack/tab group, float, fullscreen. This plate draws tile and one justified float — the scratchpad. Stacks and the layout chooser (SUPER+L, §13.5 presets) are specified in words and dashed until drawn. spec §13.2

03Active border

Windows carry no buttons and no title furniture — a hairline, a tracked mono label, and the ink border on exactly one window: the focused one. Gaps 8, radius 10, the tokens everywhere else uses. spec §12

04Motion

Fluid, not decorative: a retile eases 300ms on the standard curve, the overview gets the 450ms spatial ease, and nothing moves that isn't explaining a state change. Reduced-motion collapses all of it to opacity. spec §13.4

Sect II · Overview register

SUPER + TAB reads projects, not numbered desktops.

01Project cards

Atlas, Punar, Personal — named contexts carrying windows, agents, containers, and environment. The card wireframes the real layout; the meta row states window count and agent presence in registry vocabulary (agt_123 · active). spec §14 · §14.1

02Keyboard nav

Arrows move the selection ring, ↵ commits, and typing searches — three keystrokes from any window to any project. The underline field is the greeter's passphrase grammar reused. spec §14.2

03Mode chip

Submaps announce themselves: entering resize prints an instrument chip in the bar — RESIZE · HJKL · ESC — state, verbs, exit. Modality is never silent. spec §12.3

04Restoration

Layout memory ships first; app reopening, terminal and browser restoration, and temporary activities are future goals — drawn dashed in the grid, never claimed solid. spec §14.3 · §14.4

Sect III · Edges register

The edges of the desktop keep the same promises as its center.

01Scratchpads

Terminal, AI assistant, and notes drop over the tiling on a chord and leave on the same chord — the one float the grammar owes you. It lands on the panel surface with the panel shadow rule bent once: a floating window may cast, a tiled one may not. spec §13.6

02Multi-monitor

Remembered layouts, no off-screen lost windows, SUPER+SHIFT+RIGHT across displays, collapse and restore on dock events — required, unbuilt, and therefore a dashed row here, not a second frame. spec §15

03Personal = managed

This plate has no Personal/Managed toggle because the desktop is identical in both: enrollment annotates panels and mastheads elsewhere, and buys no different tiling, overview, or grammar. Nothing at this altitude is org chrome. spec §3.2 · design language §8

Sect IV · Implementation notes

Design mockup — the tiled desktop is Milestones 1–2; this page is the acceptance reference.

01Compositor

Wayland with Hyprland + Quickshell as the initial evaluation; the bar, overview, and scratchpads are punar-shell surfaces consuming shell/theme/punar-tokens.json. The grammar must survive the legacy-GPU fallback compositor unchanged. spec §69 · §11.8

02Milestones

M1 ships the bar, tiling, and full keyboard navigation (acceptance: no mouse required). M2 ships stacking, floating, overview, layout presets, scratchpads, and named project workspaces. spec §76

03States not drawn

Stack/tab groups, the layout chooser, drag-to-tile with the mouse, monitor-disconnect collapse, and the workspace-switch spatial slide are specified in words and will be drawn when M2 builds them. Dashed until then.
